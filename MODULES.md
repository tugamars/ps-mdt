# PS-MDT module development

PS-MDT modules are folders under `modules/<module-id>`. A module can add one or more MDT tabs, a separately built Svelte UI, client and server logic, permissions, and shared Lua definitions without modifying the core pages.

The reusable APIs described here are additive. Existing MDT pages and their behavior do not depend on them.

## Directory structure

```text
modules/
└── my_module/
    ├── manifest.json
    ├── package.json                # only needed for a module UI
    ├── vite.config.js              # only needed for a module UI
    ├── shared/
    │   └── main.lua
    ├── client/
    │   └── main.lua
    ├── server/
    │   └── main.lua
    └── web/
        ├── Main.svelte
        └── dist/
            └── main.js             # generated by the module build
```

Files are loaded as follows:

- `shared/**/*.lua` runs on the client and server.
- `client/**/*.lua` runs on the client.
- `server/**/*.lua` runs on the server.
- `web/dist/**/*` is included in the PS-MDT resource pack.

Shared scripts load before the client and server module APIs. Use shared scripts for constants and function definitions; call `MDT` helpers from client/server scripts or later event handlers.

## Manifest and registration

Create `modules/my_module/manifest.json`:

```json
{
  "id": "my_module",
  "name": "My Module",
  "author": "Your Name",
  "version": "1.0.0",
  "permissions": [
    {
      "id": "my_module.view",
      "label": "View My Module",
      "description": "Open the My Module page"
    }
  ],
  "tabs": [
    {
      "id": "overview",
      "name": "My Module",
      "icon": "extension",
      "component": "module_page",
      "permissions": ["my_module.view"],
      "jobs": ["leo"],
      "group": "operations"
    }
  ]
}
```

Register it from `modules/my_module/server/main.lua`:

```lua
local path = 'modules/my_module/manifest.json'
local manifestJson = LoadResourceFile(GetCurrentResourceName(), path)

if not manifestJson then
    print(('^1[my_module] Could not load %s^0'):format(path))
    return
end

exports['ps-mdt']:RegisterModule(manifestJson)
```

Rules:

- The manifest `id` must match the module folder and contain only letters, numbers, `_`, or `-`.
- Tab names should be unique across the MDT.
- `icon` is a Material Icons name.
- `jobs` accepts `leo`, `ems`, and `doj`. Omit it to allow all authorized MDT job types.
- Multiple tab permissions use any-of behavior. A boss retains the core boss override.
- Server callbacks must repeat all authorization checks. UI visibility and client checks are not security boundaries.
- `group` can be `operations`, `records`, `personnel`, `surveillance`, `court`, or `legal`. A custom group can be `{ "id": "tools", "label": "Tools", "icon": "build" }`.

## NUI `moduleApi`

The core passes `moduleApi` and the active `tab` to the module's default Svelte component:

```svelte
<script>
  import { onDestroy } from 'svelte';

  export let moduleApi;
  export let tab;

  let selectHost;
  let listHost;
  let mapHost;
  let selectControl;
  let listControl;
  let mapControl;

  $: if (selectHost && !selectControl) {
    selectControl = moduleApi.ui.createSelect(selectHost, {
      source: 'report-types',
      placeholder: 'Choose a report type',
      onChange: (value) => moduleApi.notify(`Selected ${value}`, 'info')
    });
  }

  $: if (listHost && !listControl) {
    listControl = moduleApi.ui.createList(listHost, {
      selectable: true,
      emptyText: 'Nothing to display',
      items: [
        { id: 1, label: 'First item', description: 'Supporting text', icon: 'description' }
      ],
      onSelect: (item) => moduleApi.notify(item.label)
    });
  }

  $: if (mapHost && !mapControl) {
    mapControl = moduleApi.ui.createMap(mapHost);
  }

  onDestroy(() => {
    selectControl?.destroy();
    listControl?.destroy();
    mapControl?.destroy();
  });
</script>

<section class="page">
  <div bind:this={selectHost}></div>
  <div bind:this={listHost}></div>
  <div class="map" bind:this={mapHost}></div>
</section>

<style>
  .page { display: grid; gap: 12px; height: 100%; padding: 20px; }
  .map { min-height: 420px; }
</style>
```

Module bundles currently use Svelte 4. Keep the Svelte and Vite versions from `modules/example_module` so the bundle remains isolated from the core Svelte 5 application.

### Permissions and scoped callbacks

```js
const mayUseTool = moduleApi.hasPermission('my_module.use_tool');
const response = await moduleApi.fetchNui('getData', { page: 1 });
```

- `hasPermission(permission)` checks the authenticated user's permissions and includes the boss override.
- `fetchNui(callback, data?)` calls only a client callback registered for the current module ID. Module authors do not supply the module ID from the browser.

Register the client callback:

```lua
MDT.RegisterNUICallback('my_module', 'getData', function(data)
    return {
        success = true,
        page = tonumber(data.page) or 1,
        items = {}
    }
end)
```

`RegisterModuleNUICallback(...)` remains available as a global and as the `ps-mdt` client export for compatibility.

### Notifications

Show a notification inside the open MDT UI:

```js
moduleApi.notify('Saved successfully');
moduleApi.notify('Unable to save', 'error');
moduleApi.notify('Refreshing data', 'info');
```

Allowed types are `success`, `error`, and `info`. The core notification service controls stacking and duration.

### Civilian, report, and case searches

Modules can search the core MDT records without creating their own client or server callbacks:

```js
const civilians = await moduleApi.search.civilians('John', { page: 1, limit: 10 });
const reports = await moduleApi.search.reports('robbery', { page: 1, limit: 10 });
const cases = await moduleApi.search.cases('CASE-42', { page: 1, limit: 10 });

console.log(civilians.items, civilians.hasMore);
```

`moduleApi.search.citizens(...)` is an alias of `moduleApi.search.civilians(...)`. Every search returns:

```ts
{
  items: Array<Record<string, unknown>>;
  page: number;
  hasMore: boolean;
  message?: string;
}
```

Searches require at least two characters. The server limits results to 50 per page, checks the corresponding core permission, and applies normal report visibility restrictions.

| Search | Required server permission |
| --- | --- |
| Civilians / Citizens | `citizens_search` |
| Reports | `reports_view` or `reports_create` |
| Cases | `cases_view` or `cases_create` |

#### Search picker with a selected record variable

Each domain has a reusable picker:

```svelte
<script>
  import { onMount, onDestroy } from 'svelte';

  export let moduleApi;

  let citizenSearchHost;
  let citizenPicker;
  let selectedCitizen = null;

  onMount(() => {
    citizenPicker = moduleApi.ui.createCivilianSearch(citizenSearchHost, {
      onSelect: (citizen) => {
        selectedCitizen = citizen;
        console.log(citizen?.citizenid, citizen?.name);
      }
    });
  });

  onDestroy(() => citizenPicker?.destroy());
</script>

<div bind:this={citizenSearchHost}></div>

{#if selectedCitizen}
  <p>Selected: {selectedCitizen.name} ({selectedCitizen.citizenid})</p>
{/if}
```

Available picker factories:

```js
moduleApi.ui.createCivilianSearch(host, options);
moduleApi.ui.createCitizenSearch(host, options); // alias
moduleApi.ui.createReportSearch(host, options);
moduleApi.ui.createCaseSearch(host, options);
```

The selected object contains the stable identifier and display fields:

- Civilian: `citizenid`, `cid`, `name`, `firstName`, `lastName`, `dob`, `phone`, and `occupation`.
- Report: `id`, `reportId`, `title`, `type`, `author`, and dates.
- Case: `id`, `case_number`, `caseNumber`, `title`, `status`, `priority`, and department fields.

#### Bind the selected ID to an input

Pass an existing input using `bindTo`. When the selection changes, the picker updates its value and dispatches standard `input` and `change` events. This means Svelte's `bind:value` is updated too.

```svelte
<script>
  import { onMount, onDestroy } from 'svelte';

  export let moduleApi;

  let reportSearchHost;
  let reportIdInput;
  let reportId = '';
  let selectedReport = null;
  let reportPicker;

  onMount(() => {
    reportPicker = moduleApi.ui.createReportSearch(reportSearchHost, {
      bindTo: reportIdInput,
      onSelect: (report) => selectedReport = report
    });
  });

  onDestroy(() => reportPicker?.destroy());
</script>

<div bind:this={reportSearchHost}></div>
<input bind:this={reportIdInput} bind:value={reportId} readonly />
```

If a visible input is not needed, use `inputName` to have the picker create a hidden form input:

```js
const casePicker = moduleApi.ui.createCaseSearch(host, {
  inputName: 'case_id',
  onSelect: (selectedCase) => {
    moduleState.case = selectedCase;
  }
});

console.log(casePicker.valueInput); // generated hidden input
```

Picker controllers expose explicit selection methods:

```js
const selectedRecord = casePicker.getSelected();
const selectedId = casePicker.getSelectedId();

casePicker.setSelected(existingCase);
casePicker.setQuery('homicide');
await casePicker.search();
casePicker.clear();
casePicker.destroy();
```

`onSelect` receives the complete selected result, or `null` when the selection is cleared. A bubbling `select` custom event is also dispatched from the picker root with the selected result in `event.detail`.

### Core-backed select options

Read options without rendering a select:

```js
const options = moduleApi.getOptions('core-tabs');
```

Or create and populate a native select in one call:

```js
const control = moduleApi.ui.createSelect(hostElement, {
  source: 'all-tabs',
  placeholder: 'Select a page',
  value: 'Dashboard',
  onChange: (value, option) => console.log(value, option)
});
```

Available sources:

| Source | Contents |
| --- | --- |
| `core-tabs` | Core MDT tabs available to the current job type |
| `module-tabs` | Registered module tabs the current user can access |
| `current-module-tabs` | Accessible tabs belonging to the current module |
| `all-tabs` | Core and accessible module tabs, grouped in the select |
| `job-types` | LEO, EMS, and DOJ |
| `report-types` | Core report types for the current job type |
| `permissions` | Permission IDs assigned to the current user |

Custom options can be used instead of a source:

```js
const control = moduleApi.ui.createSelect(hostElement, {
  options: [
    { value: 'open', label: 'Open' },
    { value: 'closed', label: 'Closed' }
  ]
});

control.setOptions([{ value: 'archived', label: 'Archived' }]);
control.setValue('archived');
console.log(control.getValue());
control.destroy();
```

An option supports `value`, `label`, and optional `disabled` and `group` fields. Creating a control replaces the current contents of its host element.

```js
const list = moduleApi.ui.createList(hostElement, {
  selectable: true,
  selectedId: 'case-42',
  emptyText: 'No cases found',
  items: [
    {
      id: 'case-42',

list.setItems(newItems);
```

### Marker-free map

```js
const map = moduleApi.ui.createMap(hostElement, {
  center: [-300, -1500],
  zoom: 4,
  minZoom: 3,
  maxZoom: 10,
  zoomControl: true
});

map.setView({ x: 425.1, y: -980.5 }, 6);
const leafletPosition = map.toMapLatLng({ x: 425.1, y: -980.5 });
map.invalidateSize();
map.destroy();
```

The helper creates the same image overlay, coordinate projection, bounds, and zoom behavior as the core map. It deliberately creates no tracking layers or markers. The raw Leaflet instance is available as `map.map` if a module needs to manage its own overlays. The module owns those overlays and must clean them up before calling `destroy()`.

Call `invalidateSize()` after showing a map that was initialized inside a hidden or resized container.

## Lua module API

### Client

Client scripts can use the `MDT` namespace:

```lua
MDT.Notify('Action completed', 'success')

local options = MDT.GetCoreOptions('job-types')

MDT.RegisterNUICallback('my_module', 'performAction', function(data, reply)
    -- Return a result synchronously.
    return { success = true }
end)
```

For asynchronous work, omit the return value and call `reply(result)` later:

```lua
MDT.RegisterNUICallback('my_module', 'performAsyncAction', function(data, reply)
    CreateThread(function()
        Wait(100)
        reply({ success = true })
    end)
end)
```

Client helpers:

| Function | Purpose |
| --- | --- |
| `MDT.Notify(message, type?)` | Show the configured game notification |
| `MDT.GetCoreOptions(source)` | Read `job-types`, `police-jobs`, `doj-jobs`, or `impound-locations` |
| `MDT.RegisterNUICallback(moduleId, callback, handler)` | Register a callback used by the scoped NUI API |

The same notification and option helpers are available to another client resource as `exports['ps-mdt']:Notify(...)` and `exports['ps-mdt']:GetCoreOptions(...)`.

### Server

```lua
ps.registerCallback('my_module:server:getProtectedData', function(source)
    if not MDT.HasPermission(source, 'my_module.view') then
        MDT.Notify(source, 'Access denied', 'error')
        return { success = false, message = 'Access denied' }
    end

    local manifest = MDT.GetModule('my_module')
    return { success = true, moduleVersion = manifest and manifest.version }
end)
```

Server helpers:

| Function | Purpose |
| --- | --- |
| `MDT.Notify(source, message, type?)` | Show the configured game notification to a player |
| `MDT.HasPermission(source, permission)` | Check the player's stored/default permission with the boss override |
| `MDT.GetModule(moduleId)` | Read a registered module manifest |
| `MDT.GetCoreOptions(source)` | Read `job-types`, `police-jobs`, `doj-jobs`, or `impound-locations` |

They are also available as same-context server exports named `Notify`, `HasPermission`, `GetModule`, and `GetCoreOptions`.

## Complete association module example

This example creates a complete module that lets an authorized user select a civilian, report, and case, then persist that association. It demonstrates:

- Module registration and permissions.
- All three core search pickers.
- Complete selected records stored in Svelte variables.
- Selected IDs synchronized into regular inputs.
- A scoped NUI callback.
- Server-side permission and payload validation.
- Database persistence.
- Notifications, form reset, and controller cleanup.

```text
│   └── main.lua

│   └── main.lua
```

### `client/main.lua`

```lua
local resourceName = tostring(GetCurrentResourceName())

```

### `server/main.lua`

This file registers the module and its server callback. The server never trusts the permission check or selected IDs supplied by the UI.

```lua
local resourceName = tostring(GetCurrentResourceName())
local manifestPath = 'modules/association_example/manifest.json'
local manifestJson = LoadResourceFile(resourceName, manifestPath)

if not manifestJson then
    print(('^1[association_example] Could not load %s^0'):format(manifestPath))
else
    exports['ps-mdt']:RegisterModule(manifestJson)
end

local function getEffectiveJobType(source)
    local jobType = ps.getJobType(source)
    local jobName = ps.getJobName(source)

    if Config.DojJobType and jobType == Config.DojJobType then return 'doj' end
    for _, dojJob in ipairs(Config.DojJobs or {}) do
        if dojJob == jobName then return 'doj' end
    end
    if jobType == Config.MedicalJobType then return 'ems' end
    return 'leo'
end

local function canAccessReport(source, reportId)
    local identifier = ps.getIdentifier(source)
    local jobName = ps.getJobName(source)
    local jobType = getEffectiveJobType(source)

    local allowed = MySQL.scalar.await([[
        SELECT 1
        FROM mdt_reports mr
        LEFT JOIN mdt_reports_restrictions mrr ON mr.id = mrr.reportid
        WHERE mr.id = ?
          AND (
              (? = 'doj' AND NOT EXISTS (
                  SELECT 1
                  FROM mdt_reports_restrictions restricted
                  WHERE restricted.reportid = mr.id
                    AND restricted.type = 'jobtype'
                    AND restricted.identifier = 'ems'
              ))
              OR (mrr.reportid IS NULL AND (? = 'leo' OR ? = 'ems'))
              OR (mrr.type = 'citizenid' AND mrr.identifier = ?)
              OR (mrr.type = 'job' AND mrr.identifier = ?)
              OR (mrr.type = 'jobtype' AND mrr.identifier = ?)
          )
        LIMIT 1
    ]], {
        reportId,
        jobType,
        jobType,
        jobType,
        identifier,
        jobName,
        jobType,
    })
    return allowed ~= nil
end

ps.registerCallback(resourceName .. ':server:associationExample:save', function(source, payload)
    if not MDT.HasPermission(source, AssociationExample.CreatePermission) then
        MDT.Notify(source, 'You cannot create record associations', 'error')
        return { success = false, message = 'Access denied' }
    end

    payload = type(payload) == 'table' and payload or {}

    local citizenId = type(payload.citizenId) == 'string' and payload.citizenId or nil
    local reportId = tonumber(payload.reportId)
    local caseId = tonumber(payload.caseId)
    local notes = type(payload.notes) == 'string' and payload.notes:sub(1, 1000) or ''

    if not citizenId or citizenId == '' or not reportId or not caseId then
        return { success = false, message = 'Civilian, report, and case are required' }
    end

    -- Verify that every referenced record still exists. A selected UI result may
    -- be stale or a malicious client may submit arbitrary IDs.
    local citizenExists = MySQL.scalar.await(
        ('SELECT 1 FROM %s WHERE %s = ? LIMIT 1'):format(
            TableMap.Players.table,
            TableMap.Players.rawFields.citizenid
        ),
        { citizenId }
    )
    local reportAccessible = canAccessReport(source, reportId)
    local caseExists = MySQL.scalar.await(
        'SELECT 1 FROM mdt_cases WHERE id = ? LIMIT 1',
        { caseId }
    )

    if not citizenExists or not reportAccessible or not caseExists then
        return { success = false, message = 'A selected record is missing or inaccessible' }
    end

    local associationId = MySQL.insert.await([[
        INSERT INTO mdt_module_record_associations
            (citizenid, report_id, case_id, notes, created_by)
        VALUES (?, ?, ?, ?, ?)
    ]], {
        citizenId,
        reportId,
        caseId,
        notes,
        ps.getIdentifier(source),
    })

    if not associationId then
        return { success = false, message = 'Failed to save association' }
    end

    if ps.auditLog then
        ps.auditLog(source, 'module_association_created', 'case', caseId, {
            associationId = associationId,
            citizenId = citizenId,
            reportId = reportId,
        })
    end

    MDT.Notify(source, 'Record association created', 'success')
    return { success = true, id = associationId }
end)
```

The table-map expression above supports the configured core framework. Values are parameterized; do not concatenate submitted identifiers into SQL.

### `sql/install.sql`

Run this once against the server database:

```sql
CREATE TABLE IF NOT EXISTS `mdt_module_record_associations` (
    `id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `citizenid` VARCHAR(64) NOT NULL,
    `report_id` INT NOT NULL,
    `case_id` INT NOT NULL,
    `notes` VARCHAR(1000) NOT NULL DEFAULT '',
    `created_by` VARCHAR(64) NOT NULL,
    `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_module_association_citizen` (`citizenid`),
    KEY `idx_module_association_report` (`report_id`),
    KEY `idx_module_association_case` (`case_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### `web/Main.svelte`

This is a complete Svelte 4 module page. Each picker returns the complete selected record through `onSelect`, while `bindTo` synchronizes the selected identifier into a normal readonly input.

```svelte
<script>
  import { onMount, onDestroy } from 'svelte';

  export let moduleApi;
  export let tab;

  let citizenHost;
  let reportHost;
  let caseHost;

  let citizenIdInput;
  let reportIdInput;
  let caseIdInput;

  let citizenPicker;
  let reportPicker;
  let casePicker;

  let citizenId = '';
  let reportId = '';
  let caseId = '';
  let notes = '';

  // These variables contain the complete result returned by the core search.
  let selectedCitizen = null;
  let selectedReport = null;
  let selectedCase = null;

  let saving = false;
  let error = '';

  $: canCreate = moduleApi.hasPermission('association_example.create');
  $: canSubmit = canCreate && citizenId && reportId && caseId && !saving;

  onMount(() => {
    citizenPicker = moduleApi.ui.createCivilianSearch(citizenHost, {
      bindTo: citizenIdInput,
      placeholder: 'Search by civilian name or ID...',
      onSelect: (citizen) => {
        selectedCitizen = citizen;
      }
    });

    reportPicker = moduleApi.ui.createReportSearch(reportHost, {
      bindTo: reportIdInput,
      placeholder: 'Search by report ID, title, type, or author...',
      onSelect: (report) => {
        selectedReport = report;
      }
    });

    casePicker = moduleApi.ui.createCaseSearch(caseHost, {
      bindTo: caseIdInput,
      placeholder: 'Search by case number, title, or department...',
      onSelect: (caseRecord) => {
        selectedCase = caseRecord;
      }
    });
  });

  onDestroy(() => {
    citizenPicker?.destroy();
    reportPicker?.destroy();
    casePicker?.destroy();
  });

  async function saveAssociation() {
    if (!canSubmit) return;

    saving = true;
    error = '';

    try {
      const result = await moduleApi.fetchNui('saveAssociation', {
        citizenId,
        reportId: Number(reportId),
        caseId: Number(caseId),
        notes
      });

      if (!result?.success) {
        throw new Error(result?.message || 'Failed to save association');
      }

      moduleApi.notify(`Association #${result.id} created`, 'success');
      resetForm();
    } catch (reason) {
      error = reason instanceof Error ? reason.message : 'Failed to save association';
      moduleApi.notify(error, 'error');
    } finally {
      saving = false;
    }
  }

  function resetForm() {
    citizenPicker?.clear();
    reportPicker?.clear();
    casePicker?.clear();

    selectedCitizen = null;
    selectedReport = null;
    selectedCase = null;
    notes = '';
    error = '';
  }
</script>

<section class="association-page">
  <header>
    <div>
      <span class="eyebrow">{tab?.name || 'Module'}</span>
      <h1>Associate MDT Records</h1>
      <p>Select one civilian, report, and case, then save the relationship.</p>
    </div>
    <button type="button" class="secondary" on:click={resetForm}>Reset</button>
  </header>
```

### Install and run the example

1. Run `modules/association_example/sql/install.sql` against the MDT database.
2. Install and build the module:

   ```powershell
   ./modules/install-all.ps1
   ./modules/build-all.ps1
   ```

3. Restart `ps-mdt` so the manifest and new module scripts load.
4. Assign `association_example.view` and `association_example.create` through MDT permission management. The role also needs the core permissions used by the pickers: `citizens_search`, `reports_view` or `reports_create`, and `cases_view` or `cases_create`.
5. Open **Record Associations** from the Records navigation group.

When adapting this example, change the folder name, manifest ID, Lua `ModuleId`, callback names, permission IDs, database table, and Vite library name together.

## Building module UIs

Copy the `package.json` and `vite.config.js` approach from `modules/example_module`, then run:

```powershell
./modules/install-all.ps1
./modules/build-all.ps1
```

The required output is `modules/<module-id>/web/dist/main.js`, whose default export is the module's Svelte component.

## Security checklist

- Validate every protected server callback with `MDT.HasPermission` or an equally strict server-side rule.
- Treat NUI payloads and client event payloads as untrusted input.
- Do not rely on a hidden tab, `moduleApi.hasPermission`, or a client callback to protect data.
- Return only the fields the module UI needs.
- Destroy select, list, and map controllers in the component's teardown lifecycle.
- Keep module IDs and callback names limited to letters, numbers, `_`, and `-`.
